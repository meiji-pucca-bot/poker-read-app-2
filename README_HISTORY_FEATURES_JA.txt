Poker Read: ハンド保存修正＋バックアップ・復習機能

この更新に含まれるもの
1. 前回のAIレビュー保存修正（キャッシュ／大会ハンドの両方）
   AIレビュー結果をハンドIDごとに保存し、「AIレビュー済み」として再表示します。
   保存に失敗した場合は画面上に残し、AIを再実行せず保存だけ再試行できます。
2. ハンド・AIレビュー・お気に入りのバックアップ／復元
3. 履歴カード上のレビュー日・一言要約・直接開くボタン
4. 点数やAI課題から絞り込める復習リスト

使い方
・キャッシュの「ハンド履歴」または大会の「ハンド履歴」を開きます。
・上の「バックアップ・復元」から「バックアップを保存」を押します。
・ダウンロードされた poker-read-backup-日時.json を安全な場所へ保存してください。
  iPhoneでは「ファイル」アプリなどで保存先を確認してください。
・復元先で同じページを開き、そのJSONを選びます。
・まだこの時点では履歴は変更されません。追加件数と競合の件数を確認します。
・復元先の現在の履歴もバックアップし、保存を確認してチェックを入れます。
・他のPoker Readのタブを閉じ、「この内容で取り込む」を押して最終確認します。
・「キャンセル」なら変更しません。
・履歴カードの「保存済みレビューを開く」は保存結果を見るだけです。
  AIの再実行や追加API料金は発生しません。
・「苦手なプレーを復習」では点数の低い順で表示します。
  種別、点数、主な課題、課題キーワードで絞り込めます。
  キーワードはAIの改善点・次の目標・ストリート別課題も検索します。

保存・復元の安全仕様
・既存履歴の消去や一括上書きはしません。
・同じIDかつ同じ内容は重複登録しません。
・IDが同じでもハンドまたはレビューの内容が異なるときは、取り込む側を
  新しいIDの別ハンドとして保全します。レビューとお気に入りもそのIDへ対応させます。
・旧形式／新形式のレビュー、未知の保存項目を維持します。
・ハンドが見つからない競合レビューは既存を残し、取り込めない件数を表示します。
  元のJSONファイルも保管してください。
・ファイル形式、バージョン、保存キー、ID重複、表示に必要な型を検証します。
  不正なファイルや不正な既存データがあれば取り込み前に停止します。
・プレビュー後に別タブ等で内容が変わった場合は、再選択を求めます。
・保存容量不足などでは、元の保存内容へ巻き戻します。
  処理中断／巻き戻し失敗時には復旧用記録を残します。「中断した取り込みを元に戻す」で
  復旧できます。別タブの新しい編集を検出した場合は、上書きせず停止します。
・復旧用記録にも容量が必要です。容量不足時に自動で履歴を削除する処理はありません。
・localStorageには複数タブを完全に排他制御する仕組みがありません。
  復元中は他のタブを閉じ、新しい記録・AIレビューを同時に保存しないでください。
・バックアップにはメモ等が含まれます。取り込み／書き出しでサーバーへ送信しません。
・元のブラウザと新しい端末は自動同期しません。JSONによる手動移行です。
・壊れた保存値も書き出しでは元のまま保全しますが、検証に通らないJSONは復元できません。
  その場合はファイルを保管し、ブラウザデータを削除しないでください。

対象範囲
対象：キャッシュ／トーナメントのハンド履歴、旧・新形式のハンドAIレビュー、お気に入り。
対象外：大会成績、Tournament Navi、VPIP/PFRセッション、入力途中のデータ、APIキー。
この更新で対象外の保存キーは変更していません。
旧レビューにはレビュー日の記録がないため「記録なし（旧レビュー）」と表示します。
ハンド保存日で代用せず、今後保存するレビューから日時が記録されます。
AIの点数や助言は学習の参考で、プレーの正解や利益を保証するものではありません。

ソースZIPの反映方法（GitHubへ反映済みの場合は不要）
1. まずPoker Readの履歴をバックアップし、現在のプロジェクトフォルダもコピーします。
2. ZIPを展開し、app、lib、tests、package.json等を同じ場所へ追加・上書きします。
   フォルダごと削除して置き換えず、ファイルを追加・上書きしてください。
3. プロジェクトのターミナルで npm ci を実行します。
4. npm test を実行します。
5. 通常の実際のOPENAI_API_KEYが設定された環境で npm run build を実行します。
   このリポジトリの既存APIコードはビルド時にもキーの設定を必要とします。
   キーをGitへコミットしないでください。
6. git add app lib tests package.json README_HISTORY_FEATURES_JA.txt TEST_RESULTS_HISTORY_FEATURES.txt
7. git commit -m "Add safe history backups and review practice"
8. git push
9. Vercelの対象コミットがReadyになったことを確認してから公開アプリを再読み込みします。

ブラウザ履歴は端末・ブラウザ・公開ドメインごとの保存です。
別のVercelプレビューURLでは元の履歴が表示されなくても、元ドメインの保存は消えていません。
確認のためにブラウザデータを削除しないでください。
